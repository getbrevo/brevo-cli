`ui_app.surface_point_list` entries accept an optional `size` at the same level as `context` — the card-size override for the widget card that placement renders (BEX-416). Each axis is a CSS length string: `"<positive integer>px"` (absolute) or `"<1-100>%"` (relative to the host slot's box), e.g. `{ "width": "280px" }` or `{ "height": "50%" }`. Both axes are optional — an omitted axis stays on the host record page's per-slot default, and an empty `size` object authors nothing (the platform stores it as no size at all). Validated shape-only in `validateUiApp`; the platform remains the authority on anything registry-dependent. Partner-authored, so it round-trips through the upload diff and write-back like `label`.

`label`, `more_info`, `redirect_link` and `modal_iframe_url` moved from the `ui_app` root into each `surface_point_list` entry (BEX-426), so an app on several slots can label each placement differently and deep-link each somewhere else — completing the per-entry migration `context` and `size` started. Hard move: `validateUiApp` refuses the root spellings by name with a migration hint, per-entry violations name their entry (`ui_app.surface_point_list["<slug>"].label: …`), and the per-type rules (actionLink: `redirect_link` required, `modal_iframe_url` refused; iframeExtension: the reverse) now run on every entry. Only `extension_type` and the server-owned `link_target` remain at the root. `brevo app create`'s UI-app flow now authors exactly one placement — the record-page prompt is a single-select — and the created-app box points at `app-config.json` for adding more placements, each carrying its own label and destination.
